## I-V из дока SIS bias: выбор «vs» рядом с Plot

**Хочется.** В доке SIS bias при Monitor строить ток от напряжения (I-V), а не только V-t и
I-t.

**Предложение.** Рядом с галочкой Plot в доке любого устройства — выбор «vs: Time / Voltage /
Current / …» из величин этого устройства. Док и так читает их за один опрос, поэтому пара
X-Y берётся из одного чтения. Куда идёт кривая — по единицам: (V, A) → «I-V» с анализом
Rn/Rj, (V, dBm) → «P-V», время → «P-t», «V-t», … Для SIS bias по умолчанию «vs Voltage».
Monitor over time при этом не трогаем.

**Ограничение.** Только величины одного устройства; прибор от прибора — следующий пункт.

## Мониторить любую величину от любой другой

**Хочется.** В доке SIS bias при Monitor строить I-V (ток от напряжения), а не только V-t и
I-t. В общем виде — любое показание любого прибора от любого другого показания: P от V SIS,
T от времени, ток катушки от тока SIS и т. д.

**Как сейчас.** Monitor over time пишет «длинную» таблицу `samples`: строка на одно значение
(время, устройство, величина, значение, единица, `plot`), график выбирается по единице
(`plot_for`: dBm → P-t, V → V-t). Док прибора с Plot шлёт пары (t, значение) в те же
графики (`GraphHub.monitor_value`). Пары X-Y из такой таблицы не собрать: значения разных
величин лежат в разных строках.

**Предложение.**
- *Данные.* Монитор пишет «широкую» таблицу `readings`: строка на один опрос — `time` и
  колонка на каждую выбранную величину (`sis_bias_1/voltage`, `power_meter_1/power`), с
  `Column(title, unit)` из величин. Значения одного опроса — одна точка, поэтому любая пара
  колонок даёт кривую. Старые файлы с `samples` продолжают строиться как сейчас.
- *Графики измерения.* `Procedure.plot_specs()` — метод экземпляра (по умолчанию
  `cls.plots`). Монитор возвращает спецификации по своему параметру `plots`: список пар «Y от
  X», где X — `time` или любая выбранная величина. Спецификации сохраняются в метаданных
  измерения, и Data → Plot строит сохранённый монитор так же.
- *Куда идёт кривая.* `plot_for(x, y)` по единицам и видам: (V, A) у SIS bias → «I-V» (с
  анализом Rn/Rj), (V, dBm) → «P-V», (время, …) → «P-t», «V-t», …, остальное — график
  «<Y>-<X>», создаётся сам. Одна функция для монитора и для дока прибора.
- *Интерфейс.*
  - Док прибора: рядом с Plot выбор «vs: Time / Voltage / …» из читаемых величин этого
    устройства. Для SIS bias сразу пресет «I-V» (одна `read_values` — пара из одного опроса).
  - Monitor over time: под деревом устройств список «Plots» — строки «Y [combo] от X
    [Time | отмеченные величины]», по умолчанию — каждая величина от времени, как сейчас.
- *Ограничение.* Величины разных приборов читаются по очереди, а не строго одновременно
  (разница — время одного опроса). Для медленного дрейфа это неважно. Если X задаётся, а не
  дрейфует, это не монитор, а развёртка — отдельная процедура (как I-V curve).

**Где.** `thzdaq_core/measurements/procedures/monitor.py` (таблица, параметр `plots`,
`plot_specs`), `measurements/procedure.py` и `runner.py` (спецификации экземпляра в
метаданных), `measurements/plots.py` (`plot_for(x, y)`), `thzdaq_gui/graphs.py` (график по
паре), `docks/devices.py` (выбор X в доке), `docks/measure.py` (`MonitorBox`: список пар).
