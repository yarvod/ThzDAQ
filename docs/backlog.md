## Решено по заметкам со стенда (2026-11-12)

Заметки ниже разобраны в обсуждении; здесь то, что решили. Группы почти не пересекаются

### 1. Окно и доки

- **Pro и перспективы убрать.** Режим Pro не использовался, перспективам применения нет.
  Остаётся одна раскладка: уходят `modes.py`, `perspectives.py`, переключатель режимов,
  ключи настроек `MODE`, `LITE_LAYOUT`/`PRO_LAYOUT`. Lite перестаёт быть режимом и
  становится просто окном.
- **Верхняя панель остаётся:** выбор измерения, Start/Stop, кнопка настроек, комментарий.
  Поле комментария шире.
- **Кнопка настроек показывает док выбранного измерения:** если он во вкладке, тот
  становится активным; если закрыт, открывается плавающим. Всплывающего окна параметров
  нет.
- **Общий док Measurement справа убрать**, с ним «заимствование» формы между доками
  (`MeasurementHost`, `DockBody.lend`, `show_controls`). У каждого измерения свой док, форма
  в нём живёт всегда; Start/Stop панели и дока — виды одного `RunModel`. Модель настройки
  измерения (параметры и приборы вне виджета) пока не нужна; понадобится, когда те же
  значения захочется показать в двух местах («повторить с параметрами» из Data, подсказка
  агента).
- **Базовые доки закреплены и без крестика**, из меню убраны: Setup и Data табами слева;
  Processes, Log, Events, Daemon табами снизу. Пин на край (auto-hide ADS) остаётся.
- **Док, у которого ещё не было места, открывается плавающим**, чтобы пристыковать его
  самому; закрытый пристыкованный возвращается на своё место.
  Графики и доки, которые открывает измерение, — по своему алгоритму.
- **Крестик прячет док, а не удаляет** (как сейчас, `DockWidgetDeleteOnClose` выключен):
  введённые значения переживают закрытие. Удаляются только доки с `closing` (файлы
  редактора).
- **Ctrl+K** не срабатывает: сделать сочетание общим на всё окно.
- **Своё измерение в списке сверху:** проверить на ветке `daemon` (шаг 9 М3 должен был
  это сделать).
- **«Новый цикл»** (предложено, не подтверждено): корень данных задаётся один раз
  (например `D:\data`), кнопка создаёт папку с датой `<корень>/2026-11-12` и открывает её
  как рабочую. Закрывает и «Папку данных на выбор» ниже.

### 2. Графики

- **Цвета кривых (баг с дублями).** Сейчас цвет считается по номеру кривой, после удаления
  номера сдвигаются. Решение (вариант а): цвет назначается кривой один раз при создании —
  первый цвет палитры, которого ещё нет на этом графике — и хранится с ней; существующие
  кривые не перекрашиваются.
- **Ключ графика и подпись раздельно:** короткий ключ (`p-t`) — имя графика, к нему
  привязаны раскладка и `into=` в скриптах; справа подпись («Pressure (time)»,
  `I-t` «Coil current (time)» вместо `Coil-t`). Подписи меняются свободно.
- **Значения у курсора:** x, y (и z у карты) рядом с мышью, плашка исчезает за границей
  графика.
- **Монитор открывает свои графики** и делает их активными, I и V в разных группах, чтобы
  видеть оба.
- **Кнопка «Показать графики»** у измерения.

### 3. Встроенные измерения и формы

- **Переименования вместе с ключами.** Старые ключи — одна таблица в api (старый → новый);
  её понимают все читатели: файлы, Data → Plot, CLI, агенты, запомненные значения форм.
- **В Data текущее название**, старое — в подсказке.
- **Каждое измерение пишет свои графики в файл** (как уже делает `m.plot`): файл рисует
  себя сам, как бы ни менялась процедура. Файлы, записанные раньше, берут графики по
  старому ключу.
- Названия: SIS I-CL curve → SIS Josephson suppression; SIS magnet demagnetization → SIS
  demagnetization; SIS P-V curve → SIS P-V measurement (без hot/cold и grid); IF amplifier
  noise (SIS shot noise) → IF health check (SIS shot noise), в группу `if`; SIS Y-factor (V)
  → SIS Tn-V; IF noise (hot/cold) → SIS Tn-IF.
- **Новое измерение Power-IF YIG:** как SIS Tn-IF, скан по частоте без hot/cold.
- **Поля по условию:** параметры hot/cold (load switch delay, hot, cold load) видны, только
  когда включён hot/cold; grid angle и grid speed — когда включён grid; так же поля прибора,
  который включается галкой. В описании параметров нужно правило «показывать, если».
- **Разделители-группы** в форме; Set LO выше LO frequency; IF switch — выпадающий список
  upper/lower.
- **2SB:** убрать питание YIG (у него свой модуль); RBW/VBW/Span прятать, если выбран
  измеритель мощности, а не анализатор спектра.

### 4. Приборы

- **Сетка: программный ноль.** Текущее положение становится 0°, абсолютный угол хранит
  программа (`ArduinoGrid.set_angle_reference`); проверить, что угол верно отслеживается по
  циклам измерений; монитор текущего угла, как значения SIS bias.
- **YIG:** монитор текущего значения.
- **Генераторы:** частота, состояние и мощность оранжевым при включённом мониторе.

### Решено позже (2026-11-12)

- **Ключи измерений** по правилу `<группа>.<что меряем>_vs_<что меняем>`; старые остаются
  в таблице старых ключей (группа 3):

  | Название | Сейчас | Новый ключ |
  |---|---|---|
  | SIS I-V curve | `sis.iv_curve` | `sis.current_vs_voltage` |
  | SIS P-V measurement | `sis.pv_curve` | `sis.power_vs_voltage` |
  | SIS Tn-V | `sis.y_factor_voltage` | `sis.noise_temperature_vs_voltage` |
  | SIS Josephson suppression | `sis.cl_curve` | `sis.current_vs_coil_current` |
  | SIS demagnetization | `sis.demagnetize` | `sis.demagnetization` |
  | SIS reflection (VNA) | `sis.reflection` | `sis.reflection_vs_frequency` |
  | IF health check (SIS shot noise) | `sis.shot_noise` | `if.amplifier_noise_vs_voltage` |
  | SIS Tn-IF | `if.hot_cold` | `if.noise_temperature_vs_frequency` |
  | Power-IF YIG (новое) | — | `if.power_vs_frequency` |
  | 2SB LO/RF balance | `two_sb.pump_balance` | `two_sb.lo_rf_balance` |
  | 2SB sideband ratio | `two_sb.srr` | `two_sb.sideband_ratio` |
  | 2SB noise temperature | `two_sb.tn` | `two_sb.noise_temperature` |
  | 2SB SRR/Tn bias optimization | `two_sb.optimization` | `two_sb.bias_optimization` |
  | SIS current versus grid angle | `grid.current_angle` | `grid.current_vs_angle` |
  | Monitor over time | `monitor.time` | `monitor.values_vs_time` |

  `two_sb.if_balance` остаётся.
- **Угол сетки переживает перезапуск демона** (группа 4). Хранится в файле состояния
  приборов демона рядом с `daemon.json`: `state.json`, у симулятора `state-sim.json`. Не в
  реестре (его видит только GUI) и не в профиле (засорит `.history/`). Записи по
  id прибора. Перед движением пишется «двигается к X», после — «стоит на X»; если при
  старте демон видит «двигается», угол неизвестен, и программа просит обнулить сетку.
  Запись всего файла атомарно (`.partial` + `os.replace`, как `daemon.json`). Пишет только
  свой демон: один на папку (`FileLock`), у симулятора свой файл. Внутри демона файл
  держит один владелец — порт ядра, адаптер JSON — с замком на запись, потому что движения
  идут из разных потоков (прогон, док прибора). Запись неизвестного прибора (профиль
  сменился) не применяется.
- **Док, который был пристыкован и закрыт, возвращается на прежнее место** (его помнит
  ADS); плавающим открывается только док, у которого места ещё не было (группа 1).
