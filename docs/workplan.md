**Перепроверка по коду (после v0.0.3).** Найдено и исправлено:

## 1. При запуске и при добавлении устройства мигают маленькие окна

**Симптом.** При старте программы (и после автообновления) мелькает много маленьких окон,
потом открывается нормальное окно. То же при добавлении устройства в Setup (канал Keithley).

**Воспроизвести.** Запустить программу с профилем, где есть приборы с доками
(`stations/2sb.example.yaml`). Или в коде: поставить на `QApplication` фильтр событий и
логировать `QEvent.Show` у виджетов с `isWindow() == True`, кроме главного окна, — при создании
`MainWindow` и после `Session.update_config` появляются десятки окон `QPushButton`, `QCheckBox`,
`QDoubleSpinBox` размером с кнопку.

**Причина подтверждена.** `docks/devices.py`, `QuantityPanel.__init__`, строка ~143:
```python
for widget in (self.btnRead, self.monitor, self.interval, self.plot):
    widget.setVisible(readable)
```
вызывается до того, как эти виджеты положены в layout, то есть пока у них нет родителя.
`setVisible(True)` у виджета без родителя показывает его отдельным окном. Панель создаётся на
каждый прибор и канал, поэтому окон много; доки пересоздаются при каждом изменении профиля —
отсюда мигание при добавлении устройства. Других таких мест нет (проверены все `setVisible`
и `show` в `thzdaq_gui`).

**Исправить.** Сначала `layout.addLayout(controls)`, потом скрывать (`setVisible(False)` /
`hide()` только когда нечего читать). Правило на будущее: не вызывать `show`/`setVisible(True)`
у виджета без родителя.

**Проверить.** Тест: фильтр `QEvent.Show` на приложении, создать `MainWindow` и сделать
`update_config` с новым устройством — показанных окон верхнего уровня, кроме главного, нет.
Проверить на Windows-сборке.

## 2. Крестик закрывает всю группу вкладок

**Симптом.** Если закрыть активную вкладку крестиком справа в заголовке группы доков,
пропадает вся группа вкладок.

**Воспроизвести.** Открыть в одной группе несколько графиков (I-V, P-V, Y-V), нажать крестик
справа в заголовке группы (не на вкладке).

**Причина подтверждена.** Крестик группы (`DockAreaHasCloseButton`) по умолчанию закрывает
всю область. В ADS есть флаг `CDockManager.DockAreaCloseButtonClosesTab` — тогда он закрывает
только активную вкладку (так было в старом приложении). Флаг не включён в
`main_window.configure_docking()`.

**Исправить.** `setConfigFlag(DockAreaCloseButtonClosesTab, True)`. Вкладки и так имеют
свой крестик (`AllTabsHaveCloseButton`).

**Проверить.** Тест: область с тремя доками, `closeArea`/крестик области закрывает один док,
два остаются.

## 3. В меню Base / Devices / Measures / Graphs не видно, что открыто

**Симптом.** В меню нет галочек у открытых доков, непонятно, где виджет.

**Причина подтверждена.** Действия `toggleViewAction()` отмечаемые (`isCheckable() == True`),
но мы ставим им иконку (`add_dock`: `action.setIcon(icon)`). В Qt у отмечаемого пункта меню
с иконкой галочка не рисуется — вместо неё иконка в рамке, на тёмной теме её не видно.

**Исправить.** В меню — без иконок, с галочкой (иконка остаётся на вкладке дока). Клик по
пункту уже открытого, но скрытого за другой вкладкой дока — поднимать его (`raise_`), а не
закрывать; закрывать — по снятию галочки.

**Проверить.** Тест: открыть док — пункт меню `isChecked()`, у пунктов нет иконок.

## 5. Убрать виды устройств `frequency_multiplier`, `sideband_selector`, `switch`

**Симптом.** При «Add device» у генератора предлагаются «Frequency multiplier», «IF sideband
switch», «Switch»; у блока питания — «IF sideband switch», «Switch». Это условности в голове
пользователя, а не устройства.

**Решение.**
- **Генератор — одно устройство**, без подустройств. Умножитель задаётся у самого генератора:
  - встроенный множитель прибора (`:FREQ:MULT`, `AgilentE8247C.set_frequency_multiplier`) —
    генератор сам принимает и показывает частоту после умножителя, адаптер не нужен;
  - OEM-голова (`set_oem_state`, `set_oem_frequency_range`, `set_oem_multiplier`) — группа
    «OEM config» в доке генератора, как в старом `signalGeneratorConfig.py` (статус, частота
    start/stop в ГГц, множитель, Apply).
  - Множитель и OEM-конфиг хранятся в профиле — см. «Настройки прибора в профиле» ниже.
- **Переключатель ПЧ и питание YIG — не устройства.** В 2SB-измерениях слот `if_selector`
  становится просто `Switchable`: в комбобоксе — все каналы блоков питания стенда. У каждого
  2SB-измерения, где участвует переключатель, своё поле «Upper sideband when the output is
  on» (вкл/выкл); как и остальные параметры, оно запоминается для следующего запуска. Слот
  `yig_power` — тоже любой `Switchable`-канал.
- Остаются только подустройства драйверов (SIS bias, катушка).

**Где.** `station/kinds.py` (удалить `ADAPTER_KINDS`), `station/ports.py` (адаптеры перенести
в процедуры 2SB или удалить), `measurements/procedures/two_sb/common.py` (слоты и параметр
полосы, выбор канала через `set_output`), `stations/*.yaml`, `station/legacy.py`, `docks/setup.py`
(кнопка Add device только у приборов с подустройствами), миграция профилей: устройства этих
видов отбрасываются с предупреждением в логе, `multiplier` переносится в настройки генератора
(см. вопрос 2), тесты станции и процедур.

**Проверить.** 2SB-измерения на симуляторах с `if_selector = power_supply_1:2` и
параметром полосы; Setup генератора без «Add device».

### Настройки прибора в профиле (решение по вопросу 2)

Два вида значений в доке прибора хранятся по-разному:

| | Примеры | Где хранится | Когда обновляется |
|---|---|---|---|
| **Конфигурация прибора** | множитель и OEM-конфиг генератора, апертура NRX, пределы каналов | профиль стенда (`settings` у прибора в YAML) | когда в доке нажали Set / Apply и прибор принял команду |
| **Уставки** | частота, мощность, напряжение, выход вкл/выкл | реестр (последние введённые значения на устройство) | при каждом Set |

Правила:
- **При подключении прибор не перезаписывается.** Из профиля и реестра только заполняются
  поля дока. В прибор значения уходят только по Set / Apply пользователя (или из измерения).
- **После подключения читаем прибор** и сравниваем с профилем: если множитель или OEM-конфиг в
  приборе другие, поле подсвечивается и рядом показано значение из прибора, с действиями
  «Записать в прибор» (из профиля) и «Взять из прибора» (обновить профиль).
- **Профиль обновляется только после успешной записи в прибор**, через `Session.update_config`
  — так же, как сохраняются смещения SIS. Уставки в профиль не пишутся: они меняются
  постоянно, а профиль должен оставаться описанием стенда.
- Какие величины считаются конфигурацией — объявляет драйвер (флаг у `Quantity`, например
  `persistent=True`): `frequency_multiplier`, `oem_state`, `oem_start`, `oem_stop`,
  `oem_multiplier` у Agilent.

**Где.** `quantities.py` (флаг `persistent`, величины множителя и OEM у Agilent и симулятора),
`station/config.py` (`InstrumentConfig.settings`), `docks/devices.py` (заполнение полей,
сравнение с прибором, запись в профиль), `settings.py` GUI (уставки в реестре).

**Проверить.** Тест: подключение не вызывает записи в прибор; Set множителя меняет профиль;
отличие прибора от профиля подсвечивается.

## 7. Док генератора: непонятно, когда уходит частота, и единицы

**Симптом.** Непонятно, в какой момент частота отправляется в прибор; неясно, в каких
единицах вводить.

**Причина подтверждена.** `QuantityPanel`: значение уходит и по кнопке Set, и по
`editingFinished` поля — то есть ещё и при потере фокуса (переход в другое поле). Поле —
`pg.SpinBox` с авто-префиксом: показывает «223 GHz», но ввод с префиксами неочевиден.

**Исправить.**
- Отправка только явно: кнопка Set или Enter в поле. Изменённое, но не отправленное значение
  подсвечивать (оранжевая рамка), после успешной записи — читать обратно и снимать подсветку.
- Рядом с полем — выпадающий **выбор приставки СИ** (решение по вопросу 4). В списке — приставка
  с единицей и множитель, например «GHz — ×10⁹», «mV — ×10⁻³», «µA — ×10⁻⁶». Значение в поле и
  показание — в выбранной единице. Выбор запоминается в реестре на устройство и величину.
  По умолчанию — разумные: частота генератора в ГГц, напряжение SIS в мВ, ток SIS в мкА, ток
  катушки в мА.
- Таблица приставок одна на всё приложение, от 10⁻¹² до 10⁹:
  p (10⁻¹²), n (10⁻⁹), µ (10⁻⁶), m (10⁻³), — (10⁰), k (10³), M (10⁶), G (10⁹). Лежит в
  `thzdaq_instruments.units` (`SI_PREFIXES`) рядом с константами `MV`, `GHZ`, ..., и
  используется полями доков, формами параметров измерений и подписями графиков. Для единиц
  без приставок (dBm, dB, deg) селектора нет; для K — только «K» и «mK».
- Подписи «Setpoint» и «Measured» разделить визуально (уставка слева, измеренное справа).

**Где.** `docks/devices.py` (`QuantityPanel`, `make_spin`), единицы — таблица в `theme` или
новом `units` модуле GUI.

## 9. Поток измерения «завис»: Start и Stop не работают

**Симптом.** Если поток не смог нормально запуститься или прибор не отвечает, док показывает
«идёт», Stop ничего не делает, Start недоступен.

**Причина (предполагается, по коду).**
- Отмена проверяется только между шагами процедуры (`ctx.check_cancel`, `ctx.sleep`). Пока
  поток стоит в вызове прибора (открытие соединения, чтение с долгим таймаутом — HTTP сетки
  30 с, повторы SIS-блока), Stop не действует.
- Состояние кнопок держится только на сигнале `running_changed`. `QtRunner._run` ловит
  `Exception`, но не `BaseException`; если поток умрёт иначе, `running_changed(False)` не придёт.
- `ProcedureBox.start` при «уже идёт» получает `RuntimeError` без сообщения пользователю.
- Ручное управление (`DeviceWorker`) — один поток на всё: один зависший вызов (например,
  Prologix) блокирует опрос и кнопки всех приборов.

**Исправить.**
- Состояния дока измерения: idle → starting («подключение к приборам…») → running → stopping
  → idle; сторожевой таймер сверяет с `thread.is_alive()` и возвращает интерфейс в idle, если
  поток кончился без сигнала.
- `QtRunner._run`: `finally` всегда шлёт `finished`/`running_changed(False)`.
- Stop → `cancel()`; если поток не завершился за N секунд, появляется **Abort**: сбросить
  соединения приборов этого измерения (пункт 10) — заблокированное чтение получает ошибку,
  поток выходит. Убить Python-поток нельзя, поэтому прерываем ввод-вывод.
- `DeviceWorker`: таймаут задания с сообщением «прибор не отвечает» и кнопкой сброса
  соединения; подумать об очереди на соединение, чтобы один зависший Prologix не блокировал
  другие приборы.

**Проверить.** Эмулятор прибора, который принимает соединение и не отвечает: Start → Stop →
Abort возвращает док в idle; повторный Start работает.

## 10. Prologix и сокеты с одним соединением: зависание и переподключение

**Как сейчас.** `TransportPool` уже держит одно соединение на адрес (Prologix по IP:порт,
сокет R&S HMP2030 по IP:порт) и раздаёт его всем приборам под общей блокировкой — второго
соединения внутри программы не появляется, потоки не мешают друг другу. Легаси-синглтон
не нужен.

**Чего нет (подтверждено по коду).**
- **Восстановления.** Если сокет умер или завис, `SocketLink` остаётся «открытым» с мёртвым
  сокетом; все приборы на нём падают до перезапуска программы.
- **Сброса буфера.** После таймаута опоздавший ответ остаётся в сокете и будет прочитан
  следующим запросом как ответ на него — рассинхрон.
- **Переинициализации Prologix.** `PrologixController` настраивается один раз
  (`_configured`), после переподключения `++mode`/`++auto`/адрес не переотправятся.
- **Видимости.** В интерфейсе нельзя посмотреть общие соединения и сбросить их.

**Исправить.**
- `Link.reset()`: закрыть, открыть, очистить буфер; `PrologixController.invalidate()` —
  настроить заново и выбрать адрес при следующем обращении.
- Автоматически: на `InstrumentTimeoutError`/`InstrumentConnectionError` соединение
  помечается сломанным; следующая транзакция сначала переподключается (запись не повторяем
  сама — повтор решает процедура/пользователь). Перед запросом после таймаута — дочитать и
  выбросить опоздавшие данные.
- `TransportPool.links()` — список соединений со статусом и тем, кто их использует;
  `TransportPool.reset(link_key)`.
- В Setup — группа **Connections**: «Prologix 169.254.156.103:1234 — Agilent 1, Agilent 2,
  FSEK 30, Keithley 1, 2», «Socket 169.254.0.30:5025 — R&S HMP2030», статус, кнопка Reset.
- Второй экземпляр программы (например, продовая и из исходников одновременно) займёт то же
  одноканальное устройство — предупреждать (lock-файл / проверка при старте).

**Проверить.** Тесты на `FakeLink`: обрыв → следующий запрос переподключается; опоздавший

## Решения по вопросам

1. **Prologix в профиле — нет**, соединения выводятся автоматически из адресов приборов и
   показываются в Setup (группа Connections, пункт 10).
2. **Множитель и OEM-конфиг — в профиле**, при подключении прибор не перезаписывается, профиль
   обновляется после успешного Set / Apply (раздел «Настройки прибора в профиле», пункт 5).
3. **Полоса ПЧ** — поле в каждом 2SB-измерении, где участвует переключатель (пункт 5).
4. **Единицы** — выпадающий выбор приставки СИ с множителем, общая таблица 10⁻¹²…10⁹ (пункт 7).
